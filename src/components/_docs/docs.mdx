# ParusUI
<br/>

## Vision

What started as a hobby challenge — can you build a full component library without any UI dependencies? — became a real project after too many bad experiences with external UI libraries. Every compromise, every workaround, every "just override the theme provider" pushed toward the same conclusion: own the code or fight it forever.

The goal is a balance between simplicity and robustness. Components are as simple as they can be while still being bulletproof — correct semantics, full keyboard navigation, screen reader support, and enough test coverage that you can customize with confidence. Deep focus on three things most libraries treat as afterthoughts: accessibility, documentation, and testing.

Built on TailwindCSS, React Hook Form, Zod, next-intl, and Popper — nothing else. No MUI, no Radix, no Chakra. Composed through props and children, never inheritance. Every element uses correct semantic HTML: Button is `<button>`, Link is `<a>` — no polymorphic shortcuts. You own every line.

<br/>

## Why ParusUI

**Complete Component System**
- **59 Production Components** — from buttons and inputs to data grids, date pickers, and multi-step forms. Everything you need to build a real application, not a demo
- **Zero UI Library Dependencies** — no MUI, no Radix, no Chakra. Every component, every style, every behavior is yours to read, modify, and own
- **Connected, Not Scattered** — components share a unified style system, consistent accessibility patterns, and a single focus management hook. This is a designed system, not a collection of copy-pasted primitives

**Built to Customize**
- **Three-Layer Style Architecture** — CSS tokens → shared style maps → component styles. Change a color token and the whole system updates. Change a style map and every component updates. Change one component without touching anything else
- **TailwindCSS v4 with OKLCH** — perceptually uniform color palettes that scale naturally. 8 palettes × 11 shades. Dark mode via a single class. No runtime CSS, no theme providers
- **3 Variants × 3 Sizes × Any Color** — `text`, `outlined`, `contained` with full dark mode, interactive states, and disabled handling built in. `className` overrides resolve automatically via tailwind-merge

**Serious Accessibility**
- **WAI-ARIA on Every Component** — semantic HTML, correct roles, proper ARIA attributes. Not bolted on — built into how each component works
- **Custom Focus System** — one composable hook handles keyboard navigation for lists, menus, comboboxes, grids, modals, and calendars. Module-level scope tree coordinates nested components without React Context — no providers, no re-renders
- **Touch Optimized** — custom `hoverable` variant prevents stuck hover states on touchscreens. Swipe gestures on Carousel and Gallery. Responsive alternatives for mobile screens

**+2100 Tests as Contracts**
- **5-Category Test Structure** — Semantics, Keyboard, Interaction, Ref, Accessibility. Every component follows the same structure. Tests double as a readable specification of what each component guarantees
- **100% jest-axe Coverage** — automated accessibility audits on every single component. No exceptions
- **Zero Snapshot Tests** — every assertion is explicit. Tests break when behavior changes, not when markup shifts

**Full Documentation**
- **Storybook Coverage** — every component has rich stories with all props connected to controls. Working examples for every implementation pattern
- **Per-Component Definition** — structured specification covering semantics, keyboard, ARIA, visual states, architecture decisions, known limitations, and review
- **24 Custom SVG Icons** — auto-sized, color-inheriting, `className`-customizable. No icon library dependency

**Integrated Form System**
- **React Hook Form + Zod** — fully wired. Every input has a standalone version and a form-integrated Field version with automatic error wiring, Label, and `aria-describedby`
- **Style Inheritance** — set variant, color, or size once on the Form, every field inside inherits it. Individual fields can override
- **TypeScript Strict Mode** — generics (`Select<T>`, `DataGrid<T>`), ref forwarding on all components, full IntelliSense

**Ready to Ship**
- **next-intl Integration** — translation JSON files for all component strings. Multi-language from day one
- **6 App-Level Hooks** — client-side filtering with 13 operators, pagination, URL-synced filters, navigation blocking, touch handling, popover positioning
- **Co-located File Structure** — component, styles, tests, stories, and docs in one folder. Atomic design hierarchy with scope-based placement

## Getting Started

Two ways to use ParusUI today, with a monorepo package planned for the future.

**Template Starter** — Clone or fork the repository and build on top. You get the full component system intact — components, styles, tests, stories, and docs. Strip what you don't need, rebrand the colors, restyle the templates. This is the intended path for new projects. The library is designed as a connected system, not isolated primitives — starting from the full template gives you everything wired correctly out of the box.

**Copy to Existing Project** — Copy `src/components/`, `src/utils/`, and `globals.css` into your existing Next.js project. Install the dependencies from `package.json`. The component system is self-contained — it doesn't import from the app layer, so it drops in cleanly. Currently Next.js only — a clean React version is planned.

**Future: Monorepo Package** — The long-term plan is to ship the component library as an internal package in a monorepo. The codebase is already cleanly separated — no components import from the app layer, styling is framework-agnostic, tests and Storybook run independently. Extraction to a monorepo workspace requires minimal work.

Once you have the components, restyle through the three-layer style system described in [Styling & Theming](#styling--theming) — change a color hue in `globals.css`, adjust shared maps in `common.style.ts`, or override individual components with `className`.

## Styling & Theming

Designed to be rewritten. No runtime CSS, no theme providers, no abstractions to learn — just TailwindCSS utility strings organized in plain TypeScript objects. The default design is deliberately minimal because every visual choice is shared. A Select trigger is a Button. A dropdown surface is a Paper. Every composite is assembled from the same building blocks that atoms use, which is why a single file — `common.style.ts` — can control the look of the entire library. You start with everything working, then add complexity only where your design requires it. No fighting an opinionated theme to get to your Figma. Clean baseline, then specialize.

### Architecture

Three file layers build the visual system — and every component can be overridden at the usage site with `className`, because `cn()` (clsx + tailwind-merge) ensures your classes always win for conflicting properties. Composite components expose inner parts through typed props (`buttonProps`, `paperProps`, `labelProps`, `scrollShadowProps`), each accepting the full prop interface including `className`, `variant`, `color`, and `size`.

**`src/app/globals.css`** — CSS custom properties. 8 color palettes (primary, secondary, terciary, dark, info, success, warning, error) x 11 oklch shades each (50–950), spacing tokens (sm/md/lg x y/x/icon), shadows (button, paper, modal, header, error, ring), z-index layers, custom Tailwind variants (`hoverable:`, `disabled-aria:`), transitions, and animations. For the full palette reference, see [Colors](?path=/story/colors--docs).

**`src/components/utils/common.style.ts`** — The shared style maps that control the visual identity of the library. Grouped by role:

**Variant maps** (variant x color) — the core style system. Each map handles one visual concern, and components compose only the maps they need:

- `baseVariant` — border, background, text color, gradient start. The foundation every styled component uses.
- `interactiveVariant` — hover, active, and selected states. Uses `hoverable:` to prevent sticky touch hover.
- `focusVisibleVariant` / `focusWithinVariant` — focus styling. Same visual treatment, different CSS selector — components that receive focus directly use `focus-visible:`, wrapper components that contain a focusable child use `focus-within:`.
- `disabledVariant` — disabled state. Intentionally flat (variant only, no color) — every disabled component uses neutral dark-* regardless of its active color.
- `textVariant` — text color per variant. Contained uses light shades, text/outlined use dark-on-light with dark mode flip.

**Size maps** — spacing, typography, and icon dimensions tied to the sm/md/lg axis:

- `paddingSize` — content padding, maps to custom spacing tokens (sm-y, sm-x, etc.).
- `iconPaddingSize` — icon-only padding, uniform on all sides, plus inline variant.
- `textSize` — font size classes, sm through 3xl.

**Shared utilities** — convenience constants reused across multiple components:

- `childrenIconSize` — descendant SVG sizing via `[&_svg]` selectors.
- `errorStateClass` — form validation error styling. The `.error` class selector triggers border + shadow.
- `toggleBaseBg` — shared background tint for checkboxes, radio buttons, switches.

All variant x color maps use `satisfies` type assertions that catch missing keys at compile time when axes are extended.

**`src/components/[level]/[name]/[Name].style.ts`** — component-specific style files. Each imports the shared maps it needs from `common.style.ts` and composes them into component-level lookup tables. A static Paper surface pulls in `baseVariant` and nothing else. A Button composes base, focus, interactive, and disabled. You pay for exactly what you use. Within each map entry, light and dark mode classes are co-located in a single string — you see the full light + dark behavior of "outlined primary hover" without jumping between files.

### How to Restyle

Every restyle maps to one of five layers. Start at Layer 1 and go deeper only if needed. The copy-paste extension model means you never guess what a new entry requires — the existing entry you copy from shows every class, every dark mode override, every state.

**Layer 1 — One component instance.** Override with `className` at the usage site. For full custom control, pass `color="none"` / `size="none"` to disable the style system entirely.

**Layer 2 — One component type, globally.** Edit existing map entries in the component's `.style.ts` file. This is always safe — you are modifying values, not structure. All Buttons need pill shape — change `rounded-md` to `rounded-full` in `buttonClass`.

**Layer 3 — One component needs a new variant.** Copy-paste an existing variant block in the component's `.style.ts`, give it a new name, change the classes. Add the new key to the `.tsx` file's prop type.

**Layer 4 — A category of components.** Add a new shared map in `common.style.ts` alongside the existing ones, or create a category-specific style file. The components that need it import the new map, everything else stays untouched.

**Layer 5 — Global design system change.** Token-level (swap a color hue, adjust spacing) — edit `globals.css`. Behavioral (change how hover or focus works) — rewrite the relevant map in `common.style.ts`. Structural (add a new color, size, or variant) — work bottom-up: `globals.css` → `types.ts` → `common.style.ts` → component `.style.ts` files. Components are built on top of each other — atoms compose into molecules, molecules into organisms. A new Button variant needs to propagate to Select triggers, DatePicker triggers, ToggleGroup — anything that renders a Button.

### Icons

24 custom SVG icons — the most common set (chevrons, check, close, search, edit, plus, minus, status icons, etc.). No icon library dependency. Most are used internally by components (ChevronIcon in Select, Calendar, Menu; CheckIcon in Checkbox; status icons in Alert), so if you rebrand you'll want to replace them. Adding more follows the same pattern — an SVG component with `currentColor` stroke and a barrel export.

Icons inherit color from their parent via `currentColor` and are auto-sized by the parent component through CSS selectors (`[&_svg]`), so they scale with `sm`/`md`/`lg` without any size prop. Direct `className` customization works on every icon. For the full icon set, see [Iconography](?path=/story/iconography--docs).

## Accessibility

Built with accessibility in mind. Components follow [WAI-ARIA](https://www.w3.org/WAI/ARIA/apg/) patterns — semantic HTML, ARIA attributes, keyboard navigation, and screen reader support are part of how each component works, not an afterthought.

**Unbreakable** — Every component's documentation includes its ARIA specification, and every component has extensive tests verifying correct ARIA attributes, roles, and keyboard behavior. Safe to customize — the docs show you what to maintain, the tests tell you if you broke it.

**Dev-Time Warnings** — `devWarning` utility fires console warnings during development for common accessibility mistakes — like an icon-only button without an `aria-label`. Tree-shaken from production builds, zero runtime cost.

**Touch & Mobile** — The `hoverable` Tailwind variant prevents stuck hover states on touchscreens — a subtle but common issue that standard `hover:` doesn't solve. Carousel and Gallery support swipe gestures. Smaller screens get responsive alternatives like MobilePagination and TabListSelect.

For keyboard navigation details, see Focus & Keyboard below.

<br/>

## Focus & Keyboard

Custom focus management system built around one composable hook — `useFocus`. Lists, menus, comboboxes, grids, modals, calendars — all handled through configuration options on the same hook. One API to learn, consistent behavior everywhere.

**One Hook to Rule Them All** — `useFocus` composes 7 sub-hooks internally (element discovery, trigger tracking, type-ahead search, keyboard routing, modal dismiss, non-modal dismiss, scope management) but exposes a single configuration interface. A combobox, a modal dialog, and a data grid all use the same hook — just different options.

**Roving Tabindex** — Focused items receive real DOM focus, not a visual fake via `aria-activedescendant`. More reliable for screen readers, works correctly with portal-rendered content and interactive children inside options.

**Scope Tree** — A module-level scope system that coordinates keyboard events across nested components without React Context — no providers, no re-renders, no props drilling. Components self-register on mount, parent-child relationships are detected via DOM containment, and the tree automatically tracks which scope is active. Built with `useSyncExternalStore` for targeted notifications. Sibling branches stay independent, closing a parent recursively closes all children.

**Extensible via Key Handlers** — Component-specific keyboard behavior added through `keyHandlers` without touching the core hook. Calendar adds 2D grid navigation with month boundary crossing. DataGrid adds a two-mode interaction model — grid navigation vs cell interaction. Menu adds hierarchical submenu navigation. Custom handlers run first and decide whether to consume the event or fall through to defaults.

**Type-Ahead Search** — Typing characters in any list or menu searches by text content — 500ms keystroke buffer, circular search from current position, case-insensitive. One option to enable on any component.

## Testing

+2100 unit tests designed as component contracts. When you customize a component, these tests tell you exactly what behavior you need to preserve — and catch you when you don't. This isn't test coverage for the sake of metrics. It's a safety net built for a library meant to be rewritten.

**5-Category Structure** — Every component's test suite is organized into the same five describe blocks: Semantics (correct HTML elements, roles, attributes), Keyboard (Enter, Space, Escape, arrow keys), Interaction (click handlers, state changes, callbacks), Ref (forwarding works via `createRef`), and Accessibility (ARIA attributes, jest-axe audit). This mirrors the documentation structure — tests double as a readable specification of what each component guarantees.

**100% Axe Coverage** — Every single component has a jest-axe accessibility audit via `toHaveNoViolations`. No exceptions, no skips.

**Behavioral, Not Snapshots** — Zero snapshot tests. Every assertion is explicit and intentional. Queries use semantic selectors (`getByRole`, `getByLabelText`) — tests break when behavior changes, not when markup shifts.

**Realistic Context** — Form fields are tested inside a custom render with `NextIntlClientProvider` (i18n) and `JestFormProvider` (react-hook-form + Zod validation). Tests run in the same context components will actually live in.

## Form Integration

Fully integrated with React Hook Form and Zod validation. Every input has a matching Field version that connects it to the form — Label, error messages, and description are wired automatically with `aria-invalid` and `aria-describedby`. Two contexts run through every form: a hook form context for state and validation, and a style context that lets the Form component theme all its fields at once — set `variant`, `color`, or `size` once on the Form, every field inside inherits it.

**Field Pattern** — Each input exists as both a standalone component (TextInput, Select, Checkbox) and a form-integrated field (TextField, SelectField, CheckboxField). The field wraps the input with React Hook Form Controller, adds Label with error/description display, and pulls styling from the form context. Consistent pattern across all 21 form components.

**Form Component** — Pass your React Hook Form definition to Form and start adding fields. The wrapper handles FormProvider, Zod validation, error distribution, and style context in one component. No boilerplate setup per form.

**StepForm** — Multi-step form built on top of Tabs with per-step validation. Future steps are disabled until reached. Parent controls routing, StepForm handles the step UI.

## File Organization

Components organized in atomic design hierarchy. The classification follows a simple rule — a component's level matches the native element it enhances. Button enhances `<button>`, so it's an atom, even though it uses InlineLoader and icons internally. Disclosure composes Button and Paper, so it's a molecule. DataGrid composes molecules into a full feature, so it's an organism.

**Co-located Structure** — Component, styles, tests, stories, and docs all live in the same folder with a barrel export. Subcomponents nest inside:

```
ComponentName/
├── ComponentName.tsx
├── ComponentName.style.ts
├── ComponentName.test.tsx
├── ComponentName.stories.tsx
├── ComponentName.docs.mdx
└── index.ts

```

**Scope-Based Placement** — Code lives at the narrowest scope that covers all its consumers. A hook used by one component stays in that component's folder (`useMenuFocus.ts` in Menu/). A hook shared across components goes in `src/components/utils/` (`useFocus`, `common.style.ts`). App-level utilities for the developer go in `src/utils/` (`cn()`, `usePopper`).

## Hooks

App-level hooks for common development patterns — used by components internally and available for your own pages and features.

**useFilterData** — Client-side filtering and sorting for any data array. 13 filter operators (equals, contains, between, in, etc.), dot-notation key access, automatic date normalization. General-purpose building block for any filtering logic. Optional server-side mode skips client filtering and exposes filter/sort state changes via callbacks.

**usePagination** — Client-side data pagination with load-more support. Resets automatically on URL search param changes.

**useSearchParamsFilter** — URL search params as typed filter state. Preserves types across serialization — arrays, numbers, booleans, dates. Default values are auto-cleaned from the URL.

**useNavigationBlocker** — Blocks navigation and shows a custom confirmation modal. Handles router.push, browser back button, and page reload. Returns `isOpen`, `proceedNavigation`, and `cancelNavigation` for your own Dialog.

**usePopper** — Popper.js positioning for portal-rendered popovers. Pre-paint positioning via `useLayoutEffect`, automatic recalculation for nested poppers.

**useTouch** — Touch device detection, long-press with configurable delay, swipe vector detection, and touch-outside handling.
