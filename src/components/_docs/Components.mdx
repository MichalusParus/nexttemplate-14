# ParusUI

ParusUI is a comprehensive component library built with focus on minimal size, reusability, and deep customization.

## Features

**Component Library**
- **58 Components** organized in atomic design structure (Atoms, Molecules, Organisms, Templates)
- **8 Custom Hooks** for common UI patterns and interactions
- **24 SVG Icons** for consistent iconography

**Styling & Theming**
- **TailwindCSS-powered** with rich theme
- **3 Variant Types** (text, outlined, contained) combinable with any color
- **Dark Mode** support with class-based strategy (`dark:` prefix)
- **Fully Customizable** via CSS variables, common styles, and className overrides

**Developer Experience**
- **TypeScript** with full type safety and IntelliSense support
- **Zero External UI Libraries** - custom-built with only React Hook Form, Zod, and Popper
- **Flexible Props** - variant, color, size, className for easy customization
- **Ref Forwarding** on all components for imperative control
- **Generic type support

**Accessibility & UX**
- **WAI-ARIA** compliant with proper roles and aria attributes
- **Keyboard Navigation** with tab order and focus traps
- **Screen Reader** support (tested with Google SR)
- **Touchscreen Optimized** with swipe gestures and disabled hover states
- **921 Jest Tests** ensuring component reliability

**Internationalization**
- **next-intl Integration** with translation JSON files for all components
- Multi-language support out of the box

**Documentation**
- **Storybook** with interactive examples, controls, and documentation

For detailed guides on styling and theming, see:
- **[Colors](?path=/story/colors--docs)** - Full color palette reference
- **[Iconography](?path=/story/iconography--docs)** - Icon system documentation

## Customization Guide

Quick guide for adapting ParusUI to your project's design system.

### Style System Overview

**Color System**

ParusUI provides **3 main brand palettes** (Primary, Secondary, Terciary) plus semantic colors (Info, Success, Warning, Error), and a neutral Dark palette. Each includes 11 shades (50-950).

For detailed color reference, see [Colors](?path=/story/colors--docs).

**Variants**

Components support **3 visual variants**:
- **text** - Minimal styling, transparent background, colored text
- **outlined** - Colored border, transparent/light background
- **contained** - Filled background with contrasting text

Combine variants with color palettes via `variant` and `color` props.
All variants have dark mode support. Enable globally or by adding `dark` class to any component. Especially useful for text and outlined variants on darker backgrounds.

**Interactive UI States**

Components have unified hover, focus, active, disabled, and selected states.
Selected is a custom "persistent active" state, enabled by passing the `selected` class to a component.
Style classes for these states are in the [common.style.ts](src/components/utils/common.style.ts) file.

For disabled styling, use the custom `disabled-aria:` variant (`.disabled[aria-disabled="true"]`) which provides enough specificity to override interactive states like hover and focus.

**Common Styles**

All main styling patterns are centralized in [common.style.ts](src/components/utils/common.style.ts). Components combine these patterns for consistency - a single source of truth. Components require all current classes to function properly, so only remove them if you're certain.

---

### Customization Steps

**1. Change Brand Colors**

Edit [globals.css](src/app/globals.css) and modify the main color schemes.

**Available variables:** `--color-primary-500`, `--color-secondary-500`, `--color-terciary-500`, plus all shades (50-950)

**2. Customize Templates**

Three layout templates are available:
- **Simple Layout** - Minimal layout for auth pages
- **Main Layout** - Standard app layout with header and footer
- **Admin Layout** - Dashboard layout with sidebar

Check the [templates folder](src/components/templates) and restyle Header, Footer, Main, Logo, and other layout components to match your design.

**3. Modify Component Variants**

For global design changes affecting all components, edit [common.style.ts](src/components/utils/common.style.ts).

**4. Component-Level Customization**

Components use common style patterns defined in [common.style.ts](src/components/utils/common.style.ts). You can copy and rewrite styles for any component if you need a more custom design, or you can add new variants or sizes.

**5. Use-Case-Level Customization**

All components use the `cn()` utility function for intelligent class merging, allowing you to fully customize any component through the `className` prop regardless of current styling.

**Setting `color="none"`** disables all color-related styles for a clean component if needed.

Complex components have subcomponent prop support, so you can customize even subcomponents.
