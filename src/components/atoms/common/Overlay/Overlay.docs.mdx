# Overlay

> Full-screen backdrop for popover dismissal. Covers the viewport as an invisible or dark-tinted click target that closes the parent popover — Dialog, Drawer, Dropdown. Manages `inert` on the app root for nested modal layering.

<br/>

## Component Definition

### Semantics & HTML
- Native `<button>` element with `type="button"` — semantically clickable without adding `role="button"` or keyboard handling to a `<div>`
- `tabIndex={-1}` — intentionally removed from tab order; the overlay is a click target, not a keyboard target
- `aria-hidden={!isOpen}` — hidden from assistive technology when closed (element remains in DOM for CSS transition)
- `aria-label` set to translated "close" when open, `undefined` when closed — announces purpose to screen readers when visible
- `data-testid="Overlay"` for test targeting
- Extends `ButtonHTMLAttributes<HTMLButtonElement>` with rest spread — consumers can pass native button attributes

### Keyboard Handling
- **Not in tab order** (`tabIndex={-1}`) — intentional. The overlay is a visual click target for pointer/touch dismissal
- **Escape key handling is the parent's responsibility** — Dialog, Drawer, and Dropdown each implement their own Escape listener. The overlay does not duplicate this concern
- No keyboard interaction on the overlay itself — correct per WAI-ARIA, since the overlay is a supporting backdrop, not a standalone interactive widget

### Accessibility (WAI-ARIA)
- No specific WAI-ARIA pattern for backdrop/overlay — this is a supporting element, not a standalone widget
- `aria-hidden="true"` when closed — prevents screen readers from discovering the invisible overlay
- `aria-hidden="false"` when open — allows screen reader to encounter it (though `tabIndex={-1}` keeps it out of tab order)
- `aria-label` with translated "close" when open — if a screen reader user encounters it via touch exploration on mobile, they know what it does
- `inert` attribute set on `#__next` app root when overlay is open — the modern replacement for `aria-hidden` on sibling containers. Prevents all interaction (focus, click, screen reader) with content behind the modal

### Visual States
- **Closed**: `invisible opacity-0` — CSS invisible, no pointer events, no layout impact
- **Open**: `opacity-100` — visible, full-screen click target, transparent background
- **Open + dark**: `opacity-100 bg-dark-950/25` — semi-transparent dark tint, used by Dialog
- Transition via `transition-colors` from the base style class

### Interaction Behavior
- Click fires `onClose` — the single interaction this component supports
- Click fires regardless of `isOpen` state (no guard) — the parent controls whether the overlay is rendered/visible
- `inert` management via `useEffect`:
  - On open: adds a unique `Symbol` to the module-level `openOverlays` Set, sets `appRoot.inert = true`
  - On cleanup (close or unmount): removes the Symbol, only clears `inert` when `openOverlays.size === 0`
  - This handles nested modals correctly — inner overlay unmounts, outer overlay keeps inert active

### Responsive & Layout
- `fixed left-0 top-0 z-overlay h-full w-full` — full viewport coverage, fixed positioning
- `cursor-default` — no pointer cursor despite being a button (intentional — looks like empty space, not a clickable widget)

<br/>

## Architecture Decisions
- **`<button>` over `<div>`**: A `<div>` with `onClick` requires `role="button"` and keyboard handling to be accessible. A `<button>` gets click semantics for free. Since keyboard interaction is intentionally excluded (`tabIndex={-1}`), the button element provides correct click handling without ARIA overhead. MUI's Backdrop uses a `<div>` with `onClick` — technically incomplete without role and keyboard support.
- **Set-based nested modal tracking**: A module-level `Set<symbol>` tracks which overlays are currently open. Each overlay instance creates a stable `Symbol` via `useRef`. This is more robust than a counter — idempotent add/delete prevents desync from React strict mode double-effects or unexpected re-renders. The Set pattern ensures `inert` is only removed when the last overlay unmounts.
- **`inert` on `#__next` app root**: The `inert` attribute is the modern standard for trapping interaction within a modal. It replaces the older pattern of manually setting `aria-hidden="true"` on sibling containers. One attribute on one element handles focus trapping, click blocking, and screen reader isolation. The `APP_ROOT_ID` constant is exported for test access.
- **Parent owns Escape handling**: The overlay is a click target only. Keyboard dismissal (Escape) is always handled by the parent popover component (Dialog, Drawer, Dropdown) because those components also need to manage focus restoration, animation timing, and other close-related logic. Duplicating Escape handling here would create race conditions and double-fires.
- **`aria-label` only when open**: When closed, the overlay is `aria-hidden="true"` and invisible — no aria-label needed. When open, the translated "close" label serves mobile screen reader users who might encounter the overlay via touch exploration.
- **Body scroll lock**: `document.body.style.overflow = 'hidden'` is set alongside `inert` when an overlay opens, and restored when the last overlay closes (nested-modal safe via `openOverlays` Set).

## Review

> The nested overlay tracking is the standout here — a module-level `Set<symbol>` that only removes `inert` and scroll lock when the last overlay unmounts. That's a problem most overlay implementations punt on entirely, and it's solved in about ten lines. Using a `<button>` for free click semantics while pulling it out of tab order with `tabIndex={-1}` is a clean trade that avoids the `div`-with-`onClick` accessibility trap.
>
> Radix's `Dialog.Overlay` handles the same scroll-lock and backdrop concerns but leans on a context-heavy compound component model with focus trapping baked in. That architecture makes sense for a sealed library, but here the parent-owns-escape split is the better call — it keeps Overlay single-purpose and lets Dialog, Drawer, and Menu each handle dismiss logic their own way without fighting a built-in trap. The `inert` attribute on the app root also replaces the `aria-hidden` sibling walk that Radix still does for broader browser support, which is a reasonable modern bet.
>
> A focused, well-reasoned overlay that earns its simplicity.
