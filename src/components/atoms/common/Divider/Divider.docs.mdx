# Divider

> Visual separator line with optional centered label. Used to divide content sections horizontally or vertically — form sections, sidebar groups, dialog zones, inline "OR" breaks.

<br/>

## Component Definition

### Semantics & HTML
- Native `<div>` wrapper element with `role="separator"` — WAI-ARIA separator, not an `<hr>` (allows flex layout and label composition)
- `aria-orientation="horizontal"` (default) or `"vertical"` based on the `vertical` prop
- Divider line rendered as inner `<div>` with `rounded-full` and color-mapped background class
- When `label` is provided, two divider lines rendered with a `<Span>` between them — the separator becomes a labeled divider
- `width` prop controls thickness (height for horizontal, width for vertical) — accepts number (px) or string CSS value, defaults to `2`
- `spanProps` forwarded to the label `<Span>`, including className (merged via `cn()`) and all other SpanProps

### Accessibility (WAI-ARIA)
- Follows [WAI-ARIA separator role](https://www.w3.org/TR/wai-aria-1.2/#separator) — non-focusable variant (purely structural, not an adjustable splitter)
- `aria-orientation` communicates directionality to assistive technology
- No `aria-valuenow`/`aria-valuemin`/`aria-valuemax` — those apply only to focusable separators (splitters)
- When label is present, the text is accessible through DOM order — no additional `aria-label` needed since the visible text already communicates the separator's purpose

### Responsive & Layout
- `flex items-center` — centers label between divider lines
- `flex-row` (horizontal) or `min-h-full flex-col` (vertical) based on orientation
- Horizontal: line has `height: width, width: 100%`; Vertical: line has `height: 100%, width: width`
- Label spacing: `mx-4` (horizontal) or `my-2` (vertical)
- `dark:text-inherit` on wrapper for dark mode text color passthrough

<br/>

## Architecture Decisions
- **`<div role="separator">` over `<hr>`**: An `<hr>` has implicit separator semantics but is a void element — cannot contain children for label layout. Using `<div>` with explicit `role="separator"` enables the two-line-plus-label flex layout while maintaining the same ARIA semantics. MUI uses `<hr>` but relies on CSS pseudo-elements for labels; Radix uses `<div role="separator">` — same approach as this component
- **Inner line as separate div**: The wrapper carries the role, ref, and className; the inner div(s) carry the visual line. This separation is necessary for the labeled case (two lines + span) and kept consistent for the unlabeled case (one line). The wrapper is always the semantic boundary; the inner divs are purely visual
- **`width` means line thickness**: A divider's only controllable dimension is its thickness — the other axis is always 100%. `width` is contextually unambiguous (like a pen's "width"), even though for horizontal dividers it maps to CSS `height`. The prop abstracts away the CSS axis swap; the JSDoc clarifies with "thickness of divider" for IDE tooltips. Default is 2px

## Review

> A clean, minimal separator that gets the semantics right. `role="separator"` with `aria-orientation` is exactly what WAI-ARIA specifies for a non-focusable divider, and the choice to use a `<div>` over `<hr>` pays off immediately — it enables the labeled variant without CSS pseudo-element gymnastics. MUI's Divider uses `<hr>` and has to fight the void element constraint with `::before`/`::after` for text alignment and `flexItem` for vertical mode. This component just flexes.
>
> The labeled mode — two lines flanking a `<Span>` — is the kind of thing Radix Separator doesn't attempt at all. Radix gives you `<div role="separator">` and stops there; label support is left to the consumer. Chakra's Divider is similarly bare — `<hr>` with no label variant. Shadcn wraps Radix and inherits the same limitation. This component fills the gap without overcomplicating the API: pass a `label` string and it just works.
>
> The `width` prop naming is a deliberate choice — a divider's only adjustable dimension is its thickness, so `width` is contextually unambiguous despite the CSS axis swap. Four color variants, orientation toggle, spanProps passthrough for label customization. No interactive behavior, no focus management, no ARIA value properties. It's a line, optionally with a word in it. That's all it should be.
>
