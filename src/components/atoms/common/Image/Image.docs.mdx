# Image

> Ratio-constrained image container wrapping Next.js Image in fill mode. Used for content images, hero banners, card thumbnails — anywhere an image needs consistent aspect ratio and object-fit control via Tailwind classes.

<br/>

## Component Definition

### Semantics & HTML
- Outer `<div>` wrapper — presentational container providing `position: relative`, `overflow: hidden`, and aspect ratio constraint via Tailwind class
- Inner element is Next.js `<Image>` in `fill` mode — renders an absolutely positioned `<img>` that fills the wrapper, with `sizes="100vw"` for responsive srcset selection
- `className` forwarded to the `<img>` element, not the wrapper — consumer styles the image directly
- `ref` forwarded to the `<img>` element (`HTMLImageElement`)
- `alt` required by TypeScript — no decorative image shortcut, consumer must provide meaningful alt text or explicit `alt=""`
- Wrapper has `data-testid="ImageRatioWrap"` for testing access (no semantic role to query by)

### Accessibility (WAI-ARIA)
- `<img>` has implicit `role="img"` — no additional ARIA attributes needed
- `alt` text is the only accessibility contract, enforced at the type level
- Follows [WAI-ARIA Images Tutorial](https://www.w3.org/WAI/tutorials/images/) implicitly via native `<img>` semantics
- `bg-dark-950/25` background visible during load provides visual placeholder but no semantic loading state

### Responsive & Layout
- `ratio` prop (default `aspect-video`) — Tailwind aspect ratio class on wrapper
- `width` prop (default `w-full`) — Tailwind width class on wrapper
- `objectFit` prop (default `object-contain`) — applied to `<img>`, options: `object-cover`, `object-contain`, `object-fill`, `object-none`, `object-scale-down`
- `objectPosition` prop (default `object-center`) — applied to `<img>`, 9 positions including corners (`object-top-left`, etc.)
- Wrapper has `max-h-full overflow-hidden` — clips to parent height constraint, prevents image bleed
- `fill` mode means `<img>` is absolutely positioned inside wrapper — wrapper dimensions are the sole size control

<br/>

## Architecture Decisions
- **`objectFit`/`objectPosition` as typed props**: Next.js 13+ removed these as native Image props. Re-exposed here as typed Tailwind class props with defaults, applied via `cn()`. Follows library convention of Tailwind classes as prop values — `width` and `ratio` use the same pattern.
- **Wrapper div for ratio**: `fill` mode requires a positioned parent. The wrapper provides `relative` positioning and aspect ratio in one element — boilerplate this component exists to eliminate.
- **Fill + ratio use case**: This component is built for ratio-constrained images using Next.js `fill` mode. For fixed pixel dimensions, use Next.js `<Image>` directly with `width`/`height` props.
- **`className` targets `<img>`, not wrapper**: Wrapper styling goes through `width` and `ratio` props. Consumer classes (`rounded-xl`, `grayscale`, `border`) land on the image element directly.
- **Server-renderable, all Next.js props exposed via rest**: No internal state, no `'use client'`. Error handling (`onError`), blur placeholder (`placeholder`, `blurDataURL`), loading callbacks (`onLoad`), `priority`, `loading`, and `sizes` all pass through to Next.js Image. Consumer owns the state when needed — Avatar demonstrates this pattern with `onError` + `useState` in the parent.
- **Lazy loading by default**: Next.js defaults to `loading="lazy"` — correct for the vast majority of images. Above-the-fold is the exception, handled by the consumer passing `priority` explicitly. No wrapper prop needed.

## Review

> This is a well-scoped wrapper — it solves exactly one problem (ratio-constrained fill images) and stays out of the way for everything else. The typed `objectFit`/`objectPosition` props are a nice recovery from Next.js dropping those, and passing `className` to the image rather than the wrapper is the right call since the wrapper's job is purely structural.
>
> Compared to shadcn/ui's AspectRatio (which is just a ratio primitive with no image opinion), this bundles the ratio container and the fill-mode image together. That's more useful out of the box for the common case, but shadcn gives you full control over what goes inside. Fair trade for a library where you can always adjust the wrapper when needed.
>
> Solid component — earns its existence by eliminating real boilerplate.
>
