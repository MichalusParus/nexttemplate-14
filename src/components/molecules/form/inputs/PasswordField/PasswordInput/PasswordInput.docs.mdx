# PasswordInput

> Password input with visibility toggle. Wraps TextInput with a toggle button that switches between masked and unmasked text. For form integration with validation and labels, use PasswordField.

<br/>

## Features

- Built-in visibility toggle button
- Start icon slot
- Error and disabled states

<br/>

## Component Definition

### Semantics & HTML
Inherits from [TextInput](?path=/docs/molecules-form-inputs-textinput-def--docs)
- Renders TextInput with `type="password"` (or `"text"` when unmasked)
- Visibility toggle button rendered as `endIcon` via Button component with `size="none"` and `hideShadow`
- Toggle button icon: `CloseEyeIcon` when masked, `OpenEyeIcon` when unmasked
- Toggle button inherits `variant` and `color` from PasswordInput props — visual consistency with the input wrapper
- `data-testid="PasswordInput"` on the native input element (via rest props to TextInput)
- No `startIcon` support — `endIcon` slot is occupied by the visibility toggle

### Keyboard Handling
Inherits from [TextInput](?path=/docs/molecules-form-inputs-textinput-def--docs)
- **Tab** — Focuses the input, then the visibility toggle button (two tab stops)
- **Enter/Space** on toggle button — Toggles password visibility (native Button behavior)
- Toggle button blocked when disabled (Button's disabled handling)

### Accessibility (WAI-ARIA)
Inherits from [TextInput](?path=/docs/molecules-form-inputs-textinput-def--docs)
- Toggle button has dynamic `aria-label` — announces current action ("show password" / "hide password") to screen readers
- `aria-label` uses `next-intl` translations — localizable

<br/>

## Architecture Decisions
- **Composition over extension**: PasswordInput renders a TextInput rather than duplicating the wrapper pattern — all visual styling (variant, color, size, error, disabled) is handled by TextInput. PasswordInput only adds the visibility toggle state.
- **Button as endIcon**: Using the full Button component for the toggle (instead of a raw `<button>`) gives consistent focus ring, disabled behavior, and keyboard handling for free. `size="none"` with `childrenIconSize` ensures the button scales with the input size.
- **`border-none` on toggle button**: The `VisibilityButton` class includes `border-none` to remove the button's own border styling — the input wrapper already provides the border.

## Review

> Clean delegation — PasswordInput does exactly one thing on top of TextInput and nothing more. The `useState` toggle driving the `type` swap is the entire component, which makes the contract easy to trust.
>
> Mantine's `PasswordInput` follows a similar architecture but bundles extra affordances: a `visibilityToggleIcon` render prop, `getVisibilityToggleButtonProps` for full control, and a built-in `visible` controlled prop. That's more flexible for edge cases like "show password by default" or swapping the icon set, but it also means more API surface to learn. This implementation trades that flexibility for simplicity — if you need controlled visibility, you'd have to modify the source. Fair tradeoff for a copy-paste library where the source *is* your API.
>
> What works well: the `Button` as `endIcon` inherits disabled state, focus rings, and keyboard access without any extra wiring, and `childrenIconSize[size]` keeps the icon proportional across input sizes. One thing worth considering: there's no `visible` / `onVisibleChange` prop pair, so a parent can't programmatically control or observe the toggle state. That's fine until someone needs it for a "confirm password" flow where both fields reveal together. A small addition when the need arises.
>
> Solid single-purpose component — the composition with TextInput carries its weight.
