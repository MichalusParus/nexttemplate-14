# Calendar

> Date picker grid component with three view modes — days, months, and years. Supports single date, range, and multi-value selection with full keyboard navigation following the WAI-ARIA grid pattern.

<br/>

## Features

- Three selection modes — single date, range, and multi-value
- Min/max date boundaries
- Unavailable dates
- Configurable week start — Sunday or Monday
- `view='day' | 'week' | 'month' | 'year'` — four independent views: `'day'` (default) renders the full month grid with year→month drill-down; `'week'` renders a single week row; `'month'` renders a standalone 3×4 month picker (`onChange` returns 1st of month); `'year'` renders a standalone scrollable year picker (`onChange` returns Jan 1st of year). Each view has its own CalendarHeader behavior (nav step, label format). Use `showHeader={false}` to hide the built-in header.
- `renderCell` — render-prop slot to fully replace the day cell (event indicators, status dots, custom layouts) while keeping selection logic, ARIA grid semantics, and keyboard navigation

<br/>

## Component Definition

### Semantics & HTML
- Wrapping `<div>` with optional `id` via `name` prop, contains a `Paper` component
- Three view modes controlled by internal `CalendarState` type: `'days'` (DayPicker), `'months'` (MonthPicker), `'years'` (YearPicker)
- Each picker renders a `role="grid"` with `role="row"` containers and `role="gridcell"` buttons
- DayPicker grid: 7 columns with `role="columnheader"` for day abbreviations, 5-6 rows of date cells
- MonthPicker grid: 3 columns, 4 rows (12 months)
- YearPicker grid: 5 columns, scrollable via ScrollShadow, year range from minMax or +-30 years
- CalendarHeader renders PreviousMonth button, MonthSelect (month+year label with chevron in month view, plain week range text in week view), NextMonth button, and an optional Today button (`showToday`)
- Roving tabindex pattern — only one gridcell has `tabIndex={0}` at any time, all others are `tabIndex={-1}`

### Keyboard Handling
Tier 4 — complex multi-axis grid navigation with cross-boundary support, managed by `useCalendarFocus` hook.

**Grid navigation (all views):**
- **ArrowUp / ArrowDown** — Move focus up/down by one row. In day view, wraps to previous/next month at grid edges.
- **ArrowLeft / ArrowRight** — Move focus by one cell. In day view, wraps to previous/next month at grid edges. MonthPicker and YearPicker stop at edges.
- **Home / End** — Jump to first/last cell in the current row
- **Enter / Space** — Select the focused gridcell (blocked when `aria-disabled="true"`)
- **Tab / Shift+Tab** — Natural Tab order through header buttons and grid cell. Arrow keys handle internal navigation between header and grid.
- **Escape** — Close the dropdown via `onClose` callback

**Day view only:**
- **PageDown / PageUp** — Navigate to next/previous month, focusing the same day-of-month (falls back to column position if the day doesn't exist)
- **Shift+PageDown / Shift+PageUp** — Navigate to next/previous year

**Header buttons:**
- **ArrowLeft / ArrowRight** — Move between header buttons. From either end, wraps into the grid.
- **ArrowDown** — Move from header into the grid (focuses cell with `tabIndex={0}`)
- **ArrowUp** — Not handled (no-op)

### Accessibility (WAI-ARIA)
- Follows [WAI-ARIA Grid Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) with roving tabindex
- `aria-selected` on gridcells reflects selection state (single, range, or multi-value)
- `aria-current="date"` marks today's date in day view, current month in month view, current year in year view
- `aria-disabled` on gridcells outside minMaxDate range or in the unavailable array
- `aria-label` on day cells uses full date format (`"Saturday, March 4th, 2023"`), month cells use month name, year cells use year number
- PreviousMonth/NextMonth header buttons have aria-labels with translated month names
- MonthSelect header button disabled when min and max dates are in the same month (no navigation possible)
- `aria-live="polite"` with `aria-atomic="true"` on the month/year label announces month and year changes to screen readers during keyboard navigation

### Interaction Behavior
- **Single date**: `date` prop sets the selected day, `onChange` fires with the clicked date
- **Range selection**: `range` prop with `start`/`end` highlights all days in the interval (excluding unavailable dates)
- **Multi-value**: `multiValue` prop highlights an array of specific dates
- **Unavailable dates**: `unavailable` prop marks dates as `aria-disabled` and blocks clicks via onClick guard
- **minMaxDate boundaries**: Dates outside min/max range are disabled, header navigation buttons are disabled at boundaries
- **State machine flow**: days -> years (click MonthSelect) -> months (click year) -> days (click month). There is no direct days -> months transition.
- **Month clamping**: MonthPicker and YearPicker clamp selected values to minMaxDate range when the chosen month/year would exceed boundaries
- **Standalone vs DatePicker**: `isActive` (default `true`) enables keyboard navigation and roving tabindex — standalone Calendars work out of the box. `focusOnOpen` (default `false`) auto-focuses the selected cell on mount — DatePicker passes this to focus the grid when the dropdown opens. Standalone Calendars let the user Tab in naturally without stealing focus.
- **`view='day'`** (default): Full month grid with year→month drill-down via CalendarHeader MonthSelect button. This is the existing behavior — internal `calendarState` drives a days→years→months→days state machine.
- **`view='week'`**: DayPicker renders only the week containing `currentMonth` (one row of 7 cells). CalendarHeader shows the week range (e.g. `"Apr 13 – 19, 2026"`) and prev/next steps by week. `onNavigate` fires when prev/next buttons or keyboard boundary crossings change the displayed week — use it to sync external state (e.g. prefetching data for the new week).
- **`view='month'`**: Standalone MonthPicker — 3×4 grid of months. CalendarHeader shows year label, prev/next step by year. Clicking a month fires `onChange` with the 1st of that month. No drill-down to days.
- **`view='year'`**: Standalone YearPicker — scrollable year grid. CalendarHeader hidden by default. Clicking a year fires `onChange` with Jan 1st of that year. No drill-down.
- **`renderCell`**: Replaces the default day-number Button with a custom node. The function receives `CalendarCellCtx` containing the date plus a pre-built `cellProps` bag (`role`, `tabIndex`, `data-date`, `aria-label`, `aria-selected`, `aria-current`, `aria-disabled`, `onClick`). Spread `cellProps` onto the wrapper element so the cell participates in keyboard navigation, selection styling, and screen-reader announcements. The Calendar still owns selection state (`isSelected`, `isDisabled`, `isToday`) and focus management — the consumer only owns visual layout.
- **`showToday`**: When `true`, CalendarHeader renders a Today button that selects today's date via `onChange`. The button is disabled when `date` is already today. Works in both month and week views.
- **External `date` sync**: When the `date` prop changes externally (e.g. URL-driven consumers), `currentMonth` syncs automatically via `useEffect` keyed on `date.getTime()`. Internal navigation (Next/Prev buttons, arrow keys at edges) is unaffected — only changes to the `date` prop value trigger the sync.

### Responsive & Layout
- Calendar width controlled by `size` prop (sm/md/lg) via `calendarWidth` style map — applies to both month and week view. Month view additionally gets a min-height via `calendarMonthHeight` (sized for 6 rows of day cells). Week view has no min-height.
- YearPicker wrapped in ScrollShadow with size-dependent height, auto-scrolls to selected year on mount
- Paper component provides border/shadow styling with `variant` and `color` pass-through

## Architecture Decisions
- **useImperativeHandle with dual refs**: `componentRef` for the outer Calendar div (exposed via `ref`), `gridRef` for the picker grid (passed to `useCalendarFocus`). The hook needs the grid ref to manage focus within the grid, while consumers need the component ref for external focus management.
- **Refs for mutable state in key handlers**: `useCalendarFocus` reads `currentMonth` and `calendarState` via refs inside `useMemo`'d key handlers to avoid stale closures during fast key repeat.
- **Cross-month boundary navigation**: Arrow keys at grid edges trigger `setCurrentMonth` and set a `pendingFocusRef` with the target position. After React re-renders the new month's grid, a `useEffect` reads the pending ref and focuses the correct cell.
- **State machine: days -> years -> months -> days**: MonthSelect toggles between 'days' and 'years' (not 'months'). Clicking a year navigates to 'months', clicking a month navigates back to 'days'. This gives users a year overview before month selection.
- **Header keydown listener with stopPropagation**: A separate `useEffect` on Calendar attaches a keydown handler for header button arrow navigation. It calls `stopPropagation()` to prevent `useFocus` (which listens on the grid) from processing the same event with stale state.
- **date-fns for all date operations**: Uses `startOfDay`, `isSameDay`, `isWithinInterval`, `eachDayOfInterval`, etc. for deterministic date comparisons. No raw Date arithmetic.
- **Dummy ref for useFocus**: A `dummyRef` is passed as `triggerRef` to prevent `useFocus` from attaching focus/blur listeners on the grid element, which would incorrectly activate `hasTriggerFocus` when the grid div gets accidentally focused.
- **PageDown/PageUp preserves day-of-month**: `pageNav` reads the focused cell's `data-date` attribute to extract the day number, stores it in `pendingFocusRef`, and the effect finds the matching day in the new month. Falls back to column position when the day doesn't exist (e.g. Jan 31 → Feb 28).
- **`aria-live="polite"` on month/year label**: The CalendarHeader wraps the month+year text in a `<span aria-live="polite" aria-atomic="true">` so screen readers announce month/year changes from keyboard navigation (PageDown, boundary crossing, header buttons).
- **`isActive` / `focusOnOpen` separation**: `isActive` controls keyboard enablement (listeners + roving tabindex), `focusOnOpen` controls focus stealing on mount. Split because standalone Calendars need keyboard without focus theft, while DatePicker needs both (auto-focus when dropdown opens). Dropdown unmounts Calendar when closed, so every open is a fresh mount — `focusOnOpen` triggers `shouldFocusGridRef` to focus the selected cell immediately.
- **`view` is the master control**: `view` determines what the Calendar renders. `'day'` uses the internal `calendarState` state machine for drill-down (days→years→months→days). `'week'`, `'month'`, and `'year'` each render a single picker with no state switching. MonthPicker and YearPicker accept an `onSelect` callback — Calendar wires it to either state-machine navigation (drill-down in `view='day'`) or direct `onChange` (standalone views). `showHeader` controls CalendarHeader visibility independently of view (defaults to `true` except `view='year'`).
- **External date sync via ref-guarded useEffect**: `lastSyncedRef` tracks the previous `date.getTime()` to avoid no-op state updates when a parent re-creates the Date instance. The useEffect only fires `setCurrentMonth` when the timestamp actually changes.
- **`cellProps` bag pattern**: `buildCellProps` in DayPicker pre-computes all required ARIA/data attributes and the disabled-guarded onClick handler. The consumer spreads this onto their wrapper element. This keeps the Calendar in control of grid semantics while giving the consumer full visual freedom.
- **`stepRange` in `useCalendarFocus`**: Arrow boundary-crossing and week/month stepping share a single helper that reads `viewRef.current` to choose `addWeeks` vs `addMonths`. The ref prevents stale closures in the memoized key handlers.

## Review

> A well-architected calendar that earns its complexity — four view modes, a drill-down state machine, keyboard navigation with cross-boundary focus management, and range/multi-select all coexist without the API feeling bloated. The `view` prop as master control is the right call; it cleanly separates "what renders" from the internal `calendarState` drill-down, so week and month views stay simple while day view gets the full state machine.
>
> React Aria's calendar builds selection and focus management into a hook-based architecture with strict ARIA grid compliance baked in, but it locks you into their state model and makes custom cell rendering an exercise in fighting abstractions. This component's approach — owning the state machine, exposing `renderCell` for custom content, and keeping keyboard logic in a dedicated hook — gives more control at the cost of maintaining focus management yourself. For a library where developers will inevitably customize day cells with event dots or status indicators, that tradeoff pays off.
>
> The `onSelect` indirection on MonthPicker and YearPicker is the cleanest part — both pickers are view-agnostic, and Calendar decides whether a click means "drill down to days" or "fire `onChange` with `startOfMonth`." Scaling from one view to four without touching the pickers themselves is a sign the abstraction boundary is in the right place.
>
> Production-ready calendar with genuine architectural depth.
